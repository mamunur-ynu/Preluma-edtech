# Secure browser/BFF contract (local implementation; staging not verified)

`api/app.py` requires a private server-to-server `PRELUMA_BFF_SHARED_KEY` of at least 32 characters. Its read endpoints accept `X-Preluma-Session` only with that key, revalidate the revocable server session on every request, and emit `Cache-Control: no-store`. The only mutation endpoints are private login/rotate/logout; learning data remains read-only. Login uses existing credential throttling; rotation conditionally consumes the old database session and inserts the replacement in one transaction. No CORS allowance is configured. This is **not** a production gateway. The API must run on a private network with TLS between trusted services. Never place the shared key or raw session token in `NEXT_PUBLIC_*`, browser JavaScript, logs or query strings.

## Intended Next.js flow

1. Next.js `POST /api/auth/login` enforces an exact configured `Origin`, a 4 KiB JSON body limit and private backend credential exchange. On success it sets only an opaque token in a first-party `__Host-preluma_session` cookie (`HttpOnly; Secure; SameSite=Lax; Path=/`, bounded age). The token never appears in browser JSON/HTML. A successful login with an existing cookie revokes the old session in the backend transaction. Login has no pre-existing session-bound CSRF token, so exact-Origin JSON-only checks protect this bootstrap mutation.
2. `GET /api/auth/csrf` revalidates the cookie against backend `/v1/me` and returns a session-bound HMAC proof; it is no-store. `POST /api/auth/rotate` and `/api/auth/logout` require both exact-Origin and that proof. Rotation changes the cookie and invalidates the old CSRF proof; logout revokes the backend token then clears the cookie. No authenticated page or browser learning mutation has been enabled. Future server components must use a server-only data-access layer and minimal DTOs; do not trust client-supplied user IDs.
3. Role changes are reflected by backend `/v1/me`; password reset/deactivation revokes or rejects sessions through existing services. The browser route derives its trusted origin from `PRELUMA_PUBLIC_ORIGIN`, never request Host or forwarding headers. Do not enable these routes publicly until gateway/IP throttling, TLS, browser-cookie persistence, CSRF, and cross-user checks pass on isolated staging.
4. Protect login/reset from enumeration and abuse using the existing shared counters plus trusted gateway-observed IP quotas. The gateway must strip untrusted forwarding headers; no application code should trust arbitrary `X-Forwarded-For`.
5. Keep Streamlit's current server-session flow working until the Next.js journey passes parity tests and a rollback rehearsal. The legacy browser-token bridge stays disabled.

## Test contract

Implemented Python tests: absent/mismatched BFF secret denied; missing/revoked/expired/deactivated session denied; role refresh observed; two users' course-enrollment views isolated; response DTO excludes password hash; catalog/learning routes remain read-only; OpenAPI v1 response shapes checked; auth login, rotation replay, new-login replacement and logout tested. A repeatable localhost synthetic HTTP smoke (`web/scripts/smoke-auth.mjs`) checks cookie flags, no session token in response body, exact-Origin rejection, CSRF rejection, re-login/rotation replay and logout revocation. `npm run typecheck` and `npm run build` compile the Next.js route handlers. These checks **do not** demonstrate a real browser retaining Secure cookies over HTTPS or a trusted gateway. Still required before AUTH-01 can close: isolated staging TLS/private-network checks, browser cookie/CSRF behavior, proxy-header/IP throttling, role elevation, cross-user authenticated web views and a secret-in-client-bundle check.
